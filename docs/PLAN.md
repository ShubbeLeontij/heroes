# План реализации: компьютерные «Герои»

## Решения, принятые с пользователем

| Вопрос | Решение |
|---|---|
| Платформа | Консоль (терминал) и графический интерфейс на Tkinter (`--gui`) — оба над одним движком. Гость сетевой партии может играть и в браузере (телефон Android/iOS, планшет, ПК; вертикально и горизонтально): страницу и WebSocket раздаёт сервер хозяина на том же порту (`heroes/net/web.py`, `heroes/web/static/`), только подключение — создавать партии в браузере нельзя |
| Язык | Python 3.13 (уже установлен; Node нет) |
| Игроки | 2–4 места, на каждом — человек, человек по сети, Claude или случайный бот; выбор в мастере при запуске. Несколько людей — за одним компьютером (hotseat) и/или по сети (`heroes/net/`: партия на компьютере хозяина, гости подключаются тонким клиентом по TCP) |
| ИИ | Claude, вызывается через Claude Code CLI (`claude -p`), модель `claude-opus-5-5` |
| Протокол | Текстовый, понятный Claude: описание состояния + вопрос, ответ — JSON по схеме |
| Интерфейс | Консоль — текст; в окне карта — рисунок из правил (подготовлен `tools/build_map.py`), планшет — свой, схематичный |
| Фракции | Все шесть фракций первой коробки: люди, нежить, гномы, орки, эльфы, наги. В движке — параметр `Game(factions=[...])`, хранятся в сохранении. Фракцию каждого места выбирает хозяин партии: в консольном мастере, флагом `--factions`, в окне «Новая партия» (сетевому гостю — тоже хозяин). Каждой фракцией играет **только один игрок**, как в коробке (у фракции один планшет); «случайная» — из тех, что никто не выбрал. Без `--factions` все места — «случайная» |
| Значки фракций | Наука, ярость, нота, крак, проклятый регион — вырезаны из памятки (с. 2, блок «Фракции»), гидра — голова с рисунка на с. 16 правил, в круге (`tools/build_icons.py`). Рисунки чудовищ у наг такие же, как у всех (подтверждено): их линия отличается только силой и наградами |
| Случайный бот | Пользуется особыми свойствами фракций наугад (покупает ОП, проклинает, обводит ноты, призывает гидру…) |
| Таверна | Считает **все** обведённые чудовища, включая обведённые за победы над игроками |
| Артефакт Содмура (люди) | +1 ПО в конце игры за каждую захваченную крепость |
| Профили | Профилей на одном компьютере может быть несколько (`profiles/`, `heroes/profiles.py`); их редактируют на отдельном экране окна. В профиле — имя, аватарка и статистика: только доигранные партии, для себя и каждого соперника — фракция, **номер хода = место в очерёдности** (1 — первый игрок первого раунда) и ПО. Аватарка — своя картинка или силуэт; у Claude и ботов — готовые аватарки (человечек из Claude Code, робот) в четырёх цветах мест. В партии аватарка стоит перед именем игрока везде в окне, а на карте заменяет фишку (вдвое крупнее прежней); свои аватарки идут всем через `static["avatars"]` (гость присылает свою в `hello`). Профиль выбирается в мастере новой партии (активный — на первое место «Человек»), новое имя человека за окном создаёт профиль; гость сети пишет партию в свой активный профиль |
| Сражения в нескольких регионах | Разыгрываются **по очереди**, как в правилах (сначала с участием первого игрока): игроки следующего сражения заявляют войска, уже зная исход предыдущего. Одновременны только заявки внутри одного сражения |
| Вопросы без выбора | Движок их не задаёт (`Decision.forced`) и не пишет в журнал решений: последнему — единственный оставшийся стартовый регион; строительство, когда нечего построить и некого нанять; перемещение, когда ОП не хватает ни на один соседний регион; заявка войск в бою, когда войск нет; штурм крепости и бой с чудовищем, когда не победить даже всеми войсками; награда, когда вариант один (только чудовище, единственный артефакт, ресурсы, которые можно забрать все или которые одного вида у одного проигравшего). Старые сохранения (версия 1, где такие решения записаны) загружаются как раньше |

## 1. Архитектура

Главный принцип: **движок не знает, кто игрок**. Когда кому-то нужно что-то решить, движок формирует запрос `Decision` (текст, допустимые варианты, проверка ответа) и синхронно вызывает `Player.decide()`. Отвечать может человек в консоли, Claude или случайный бот для тестов: у всех троих один интерфейс.

```
heroes/
  data/
    map.json              # карта и чудовища (единственный источник)
    factions/*.json       # планшеты фракций: humans (см. Приложение А), undead, dwarves, orcs, elves, nagas
  heroes/
    engine/
      state.py            # GameState, PlayerState (dataclasses, сериализуемые в JSON)
      data.py             # загрузка и валидация map.json / factions/*.json
      decisions.py        # Decision + общие проверки ответов
      effects.py          # производные характеристики: сила, цена найма, стоимость перемещения
      economy.py          # получение ресурсов («любой», замена дерева), оплата, отметки ПО
      game.py             # главный цикл: setup → 16 раундов → подсчёт; опрос игроков
      actions.py          # добыча, строительство/наём, Башня иллюзий
      movement.py         # очки перемещения, поиск пути (Дейкстра с порталами), посещение
      combat.py           # сражения: игроки, крепости, чудовища; награды; артефакты
      scoring.py          # подсчёт ПО
    players/
      base.py             # Player.decide(decision, view) -> choice
      random_bot.py       # случайные легальные ходы (для тестов и симуляций)
      console.py          # человек в терминале
      claude_cli.py       # Claude через `claude -p`
    protocol/
      view.py             # что видит конкретный игрок (с учётом тайных решений)
      render_text.py      # текстовая отрисовка планшета/карты/лога
      prompts.py          # системный промпт и тексты вопросов для Claude
      schemas.py          # JSON-схемы ответов для каждого типа Decision
      snapshot.py         # состояние и решения данными (JSON) — для графического интерфейса
    net/                  # игра по сети: сервер на компьютере хозяина, клиенты (консольный и окно)
    gui/                  # графический интерфейс (Tkinter): окно получает те же сообщения, что сетевой клиент
      links.py            # связь окна с партией: своя (движок в потоке) или чужая (по сети)
      app.py, mapview.py, boardview.py, panels.py, dialogs.py
      assets/map/         # картинки карты: основа без объектов, слой объектов, тени регионов; границы регионов
      assets/icons/       # иконки ресурсов (и ярости, науки, краков), нот, гидры, проклятия; icons.py рисует их
                          #   вместо меток, которые пишет common.res()
      assets/avatars/     # готовые аватарки 128×128: Claude, бот, человек — в цветах мест (tools/build_avatars.py)
      profileview.py, avatars.py   # экран «Профили игроков»; аватарки любого размера (PNG и уменьшение — без Pillow)
    profiles.py           # профили игроков и статистика доигранных партий
    cli.py                # запуск: `python -m heroes --players human,claude,claude`
  tools/build_map.py      # готовит heroes/gui/assets/map из docs/boards/map*.{jpg,png} (нужны Pillow, numpy, OpenCV)
  tools/build_avatars.py  # готовые аватарки (без внешних зависимостей)
  tools/build_icons.py    # значки и картинки heroes/gui/assets/icons: ресурсы и чудовища с планшетов, значки из памятки
                          #   (и значки фракций), гидра из правил, артефакты с карты
  tests/
```

Эффекты зданий и артефактов описаны в JSON фракции типизированными записями (`hire`, `set_strength`, `on_monster_win`, …), движок их интерпретирует. Новая фракция с похожими механиками добавляется одним JSON-файлом, а уникальные механики (проклятия, гидра…) потребуют новых типов эффектов.

Внешних зависимостей в ядре нет. Для тестов нужен pytest в виртуальном окружении (`python -m venv .venv`).

### Состояние и сохранения
- Всё `GameState` сериализуется в JSON: сохранение и загрузка партии, воспроизведение для отладки.
- Каждое решение пишется в журнал `logs/<game-id>.jsonl`: кто решал, что видел, что ответил, сколько попыток понадобилось Claude.
- Случайности в игре нет: кубиков и колод нет. Партия полностью воспроизводится по журналу решений.

### Тайная информация
По правилу открытости все планшеты видны всем, **кроме** двух моментов:
1. выбор региона назначения при перемещении;
2. заявка войск на сражение между игроками.

Для них движок сначала собирает решения от всех участников, никому их не показывая, и только потом раскрывает. ИИ-игрокам такие запросы можно задавать параллельно.

Решения особых механик фракций (у людей не возникают). У каждого — своя форма в окне (`gui/panels.py`), свой диалог в консоли (`players/console.py`) и схема ответа Claude (`protocol/schemas.faction_spec`); случайный бот отвечает на них наугад. Перемещение гидры наги спрашивается тайно вместе с выбором региона назначения: один и тот же Claude или сетевой игрок отвечает на эти два вопроса по очереди.

| Вид (`kind`) | Фракция, источник | Тайно? | Ответ |
|---|---|---|---|
| `raise_action` | орки, Дом вождей перед перемещением (в строительстве это шаг `raise`) | нет | `{"<действие>": X}` — на сколько поднять перемещение и уже выполненную в раунде добычу |
| `buy_move_points` | нежить, Катафалк | нет | число купленных ОП |
| `hydra_destination` | наги | **да** | регион, куда идёт гидра (вместе с выбором региона назначения) |
| `make_lake` | наги, Гейзер | нет | `true`/`false` |
| `curse_region` | нежить: Чумной столб (можно `null`), артефакты Дорталя и Содмура | нет | регион |
| `exchange_on_gain` | нежить, Часовня | нет | `true`/`false` |
| `battle_upgrade` | эльфы, Лавка бронника | в бою игроков **да** | сколько единиц модифицировать (движок берёт самые выгодные). Спрашивается, только если в заявке войск нет поля `upgrade` (старые сохранения, случайный бот) |
| `circle_note` | наги | нет | `open` (начать пару) / `close` (закрыть пару и призвать гидру) |
| `summon_hydra` | наги | нет | озёрный регион |
| `avoid_battle` | наги, Шахта | нет | `null` или `{"wood": n, "iron": n, "gold": n}` — по 3 каждому сопернику в регионе |

Каждый `Decision` содержит:
- машинное описание допустимых вариантов, по которому проверяется ответ;
- человекочитаемое описание, которое показывается и человеку, и Claude.

## 3. Протокол для Claude

**Сессия.** На каждого ИИ-игрока заводится одна сессия Claude на всю партию: `--session-id <uuid>` при первом вызове, `--resume <uuid>` дальше. Так Claude помнит свою стратегию и ход партии, а промпт каждого вопроса остаётся коротким.

**Команда** (реализация — `heroes/players/claude_cli.py`). Для каждого решения:
```
claude -p --model claude-opus-5-5 --tools "" --strict-mcp-config --setting-sources "" \
  --output-format json --json-schema '<RESPONSE_SCHEMA>' \
  --resume <session-id>          # на первом ходу: --session-id + --system-prompt-file
```
Текст вопроса передаётся через stdin.
- `--tools ""`, `--strict-mcp-config`, `--setting-sources ""`, запуск из пустой папки `~/.cache/heroes-claude`: Claude только отвечает и не подтягивает проектную память, хуки, MCP и CLAUDE.md пользователя. `--bare` не подходит: он требует `ANTHROPIC_API_KEY` и не работает со входом по подписке.
- **Схема ответа одна на все вызовы:** `{"answer": <любой JSON>, "comment": "…"}`. `--json-schema` превращается в инструмент, а инструменты стоят в самом начале запроса. Поэтому разная схема на каждый вопрос сбрасывала бы кэш промпта, и каждый вызов заново оплачивал бы всю историю партии; на опыте это было в 4–5 раз дороже. Точная схема `answer` для решения (с enum допустимых вариантов) передаётся текстом в вопросе, строгую проверку делает движок.
- В ответе `total_cost_usd` — накопленная стоимость всей сессии, а не одного вызова.
- Опционально: `--effort` (low…max).

**Системный промпт** (один раз, при создании сессии; `heroes/protocol/prompts.py`):
- правила, сжатые под игру и с трактовками этой версии;
- полный планшет фракции: здания, войска, артефакты, стоимость перемещения;
- статичная карта: регионы, местность, ресурсы, объекты, соседи; линия чудовищ;
- протокол: ответ JSON, `comment` — замысел в 1–2 фразах (соперники его не видят).

**Каждый вопрос:**
```
СОБЫТИЯ С ПРОШЛОГО ВОПРОСА: (лог партии)
ПЛАНШЕТ / СОПЕРНИКИ / СОСТОЯНИЕ КАРТЫ   — только для «крупных» решений (действия, строительство,
                                          перемещение, встречи, бой, награда, бронь)
ВОПРОС (тип, раунд): текст движка с вариантами
ФОРМАТ: как заполнить answer + JSON-схема answer
```
Для мелких решений (распределить ресурсы, чудовище, крепость, артефакт) вместо планшета идёт строка со складом.

**Ошибки.** Нелегальный ответ — Claude получает текст ошибки и отвечает заново (до 3 раз), потом безопасный вариант по умолчанию и предупреждение в журнале. Сбой CLI или ответ не по схеме — до 2 повторов вызова.

**Параллельность.** Тайные одновременные решения (7, 9) у Claude-игроков идут одновременно в потоках; человек отвечает в основном потоке. В журнал решения пишутся в фиксированном порядке, поэтому сохранения воспроизводятся однозначно.
Несколько тайных решений одного Claude-игрока (перемещение наги и её гидры) — один вопрос и один вызов: `answer` — объект `{"destination": …, "hydra_destination": …}` (`Game.ask_all` → `decide_together`); отклонённую движком часть Claude получает отдельным вопросом. Эльф с Лавкой бронника вместе с заявкой войск (в сражении, на крепость, на чудовище) сразу отвечает, сколько единиц модифицировать (`answer.commit`, `answer.upgrade`): это поле `upgrade` ответа движку, отдельного вопроса `battle_upgrade` нет.

**Сохранения.** Номера сессий Claude хранятся в сохранении (`meta.claude_sessions`); после загрузки Claude продолжает ту же сессию и получает пометку «партия загружена» и хвост событий.

**Замеры** (Opus 5.5, effort по умолчанию): ≈6 с и ≈$0.03 на решение при работающем кэше; партия — порядка 100–150 решений на Claude-игрока, то есть ≈$3–4 и 10–15 минут на игрока. Диалоги пишутся в `logs/claude/<сессия>.jsonl`.

## 4. Этапы

### Этап 0. Каркас и данные ✅
- Структура пакета, `pyproject.toml`, venv, pytest.
- `data/map.json` и `data/factions/humans.json` (Приложение А).
- Загрузчик с проверками: граф симметричен, все имена существуют, у каждого региона ровно один объект, для каждого числа игроков граф связен.

**Готово, когда:** тесты на данные зелёные.

### Этап 1. Ядро раунда без карты ✅
- `GameState`, подготовка (стартовые 2 солдата, регионы по числу игроков, выбор стартовых порталов).
- Раунд: выбор действий первым игроком, выполнение по возрастанию, смена первого игрока, 16 раундов.

## 5. Правила, которые я буду трактовать так (поправь, если не согласен)

1. **Вычеркнутые регионы** (при 2–3 игроках) нельзя проходить насквозь: они как бы не существуют.
2. **Ратуша** даёт 1🎁 при первом посещении каждого нового для игрока региона после её постройки. Регионы, через которые игрок прошёл без остановки, не считаются.
   **Стартовый регион** (подтверждено) считается посещённым во всех смыслах: в самом начале каждый получает его ресурсы, а для Шог Ида он учитывается как посещённый горный.
3. **Позиции в общем регионе:** каждый объявляет «сражаться», «претендую на крепость/артефакт» или «пас». Бой начинается, если кто-то выбрал «сражаться» или претендентов больше одного. «Уступить» означает выбрать «пас». Движок предлагает только варианты, ведущие к разным исходам: если кто-то уже выбрал «сражаться», «пас» не предлагается (сражение будет всё равно), а «претендовать» остаётся, только если от сражения можно откупиться Шахтой наг; «пас» не предлагается и тогда, когда «претендовать» лишь даёт право на объект (например, второй из двоих после «паса» первого) — от крепости и артефакта можно отказаться потом; если все варианты равносильны, игрока не спрашивают.
4. **Награда ресурсами проигравших:** если у проигравших ресурсов меньше разницы сил, победитель забирает сколько есть.
5. **Бой с чудовищем** доступен только в раунде, где было действие перемещения, даже если игрок остался на месте.
6. **Захват крепости без соперников:** игрок, оказавшийся в регионе один, может штурмовать её до боя с чудовищем, отдельной заявкой войск.
7. **Башня иллюзий:** выбранный портал перестаёт работать для всех остальных, а сам владелец пользуется им как обычно.
8. **Шог Ид** (условие «4 посещённых горных региона»): учитываются горные регионы, где игрок **заканчивал** перемещение, включая стартовый, если он горный. Из четырёх стартовых регионов с порталом горный только Карракс.
9. **Рынок** (+2🎁 при победе над чудовищем) срабатывает только в бою с чудовищем, не при победе над игроком.
10. **Фундамент** (решено с пользователем): если игрок построил здание, стоя в регионе с доступным ему фундаментом, и уровень здания выше вписанного, движок возводит здание на фундаменте **автоматически**, без вопроса.

### Фракции первой коробки

Подробные заметки — в поле `notes` каждого `data/factions/*.json`. Решено с пользователем:

11. **Дом вождей (орки):** во время строительства или перемещения орк может платить яростью: каждая оплата X поднимает уровень одного действия на X. Поднять можно текущее действие и добычу, уже выполненную в этом раунде: она сразу приносит ещё X ресурса. Уровень может быть выше 4.
12. **Гидра рядом с нагой** — обычная боевая единица: победа с её участием даёт обычную награду (ресурсы чудовища, крепости).
13. **Отдельная гидра** без игроков в регионе может штурмовать крепость своего региона и сражаться с чудовищем линии наги. Это бой наги с чудовищем в этом раунде: не больше одного на войско и гидру вместе. Победа отдельной гидры даёт только ПО, ресурсы теряются, гидра погибает.
14. **Сражение с отдельной гидрой:** в регионе гидры никто ничего не получает — ни награды, ни крепости, ни артефакта; победитель только обводит чудовище. Победа гидры не мешает наге в своём регионе брать артефакт, штурмовать крепость и сразиться с чудовищем (следующим в линии) — уже краками.

Трактовки движка (поправь, если не так):

15. **Проклятие** при посещении срабатывает, когда соперник **закончил перемещение** в проклятом регионе, сменив регион; оставшийся на месте его не посещает. Самая слабая единица — по силе в этот момент (палач — по ОП этого раунда, механик — 0, крак — по числу краков); при равенстве гибнет та, что выше на планшете. Чумной столб: «соседний» — по границам карты, без порталов.
16. **Механики гномов** и **Лавка бронника эльфов** усиливают самые выгодные из заявленных единиц автоматически (выбирать хуже незачем): игрок выбирает только, сколько единиц модифицировать в Лавке бронника.
17. **Гнездовье эльфов:** если артефакт можно взять и за дерево, движок берёт дерево вместо 12 ресурсов; если обычное условие (не оплата) выполнено — артефакт бесплатный.
18. **Строительство — цикл шагов** (правила, с. 6: «в любой последовательности»): здание (одно), наём (сколько угодно раз), **модификация войск орков**, **Дом вождей** (повышение этого строительства и прошедшей добычи) и **Библиотека** (один обмен за действие) — в любом порядке, каждый шаг сразу даёт свои эффекты (ярость Арены, наука Цеха и Генератора, ресурсы Сборщиков). Башня иллюзий и Чумной столб — в конце действия. Наём считается по единице: наука Цеха сразу удешевляет следующих по Конвейеру.
19. **Гейзер** спрашивается сразу после перемещения, до сражений: потраченное ОП уже не пропускает чудовище, а новая местность действует в сражениях этого раунда.
20. **Шахта** отменяет сражение, когда оно вот-вот начнётся (кто-то хочет сражаться или претендентов несколько); единственный претендент после этого получает объект, при нескольких — никто. Плата раскладывается соперникам по 3 в порядке дерево → железо → золото.
21. **Бонусы к силе** (Горн, Металка, Золен эльфов) действуют и при пустой заявке: с ними можно драться с чудовищем и штурмовать крепость, никого не заявив.
