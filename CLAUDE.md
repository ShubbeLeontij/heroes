# Правила работы над проектом

## Завершение фичи или фикса

1. Пока идёт работа, тесты гонять выборочно — только те, что относятся к изменению. Весь набор не нужно.
2. Когда фича или фикс готовы, показать результат человеку и дождаться его подтверждения, что всё сделано правильно.
3. После подтверждения:
   1. прогнать **все** тесты (`.venv/bin/python -m pytest`); если что-то упало — чинить, а не коммитить;
   2. поднять версию по semver (`version` в `pyproject.toml`): фикс — patch, новая совместимая фича — minor,
      несовместимое изменение — major;
   3. закоммитить изменения вместе с новой версией;
   4. поставить на коммит тэг с номером версии без префикса (например `1.2.3`);
   5. запушить коммит и тэг (`git push` и `git push origin <тэг>`).

## Релиз после пуша

После пуша коммита и тэга:

1. Собрать `dist/heroes_<major.minor.patch>.zip` (папка `dist/` в `.gitignore`, все zip хранятся там) — только то, что нужно
   для запуска, без материалов для разработки. Внутри архива всё лежит в папке `heroes_<версия>/`:
   - `heroes/` (код, вместе с `heroes/web/`; без `__pycache__`);
   - `data/`;
   - `docs/RULES.md`, `docs/MAP.md`, `docs/CLI.md` (`RULES.md` читает Claude-игрок);
   - `README.md`, `pyproject.toml`.

   Не включать: `tests/`, `tools/`, `docs/rules/` и `docs/boards/` (PDF и сканы), `docs/PLAN.md`, `.git`, `.venv`,
   `saves/`, `logs/`, `profiles/`, `strategy/`, `dist/`, `CLAUDE.md`.
2. Создать релиз на GitHub с этим архивом: `gh release create <версия> dist/heroes_<версия>.zip --title <версия> --generate-notes`.

## Работа над GitHub issue

Если задача — это GitHub issue, то:

1. Разработку вести в отдельной ветке от `master`, а не в самом `master`. Имя ветки: `issue-<номер>-<кратко-латиницей>`.
2. После подтверждения человека пройти шаги из «Завершение фичи или фикса» в этой ветке: все тесты, версия по semver,
   коммит. Тэг пока не ставить.
3. Запушить ветку и открыть PR в `master`. В описании PR написать `Closes #<номер>` и указать хеш коммита (коммитов) с
   решением, чтобы issue закрылся вместе со вливанием PR и осталась ссылка на коммит.
4. Влить PR самому (`gh pr merge <номер> --merge`), отдельного разрешения человека не ждать: подтверждение по пункту 2
   уже получено.
5. После вливания PR перейти на обновлённый `master`, поставить тэг с версией на итоговый коммит в `master`, запушить тэг и
   выполнить «Релиз после пуша».
